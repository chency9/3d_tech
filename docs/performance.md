# 保持模型精度的渲染优化

模型文件、顶点、三角形、材质参数、抗锯齿、像素比与 2048×2048 阴影设置均保持原样。优化集中在绘制提交和重复计算。

## 测量结果

对照版本：`78f4f61`。环境：Windows、Chrome Headless、WebGL 2、1440×1000、DPR 1，支持 `WEBGL_multi_draw`。每种状态预热 12 帧，采样 60 帧；计时期间姿态持续变化。固定时间 2.25 秒另行捕获画面，以便对比。

| 状态 | 每帧绘制调用：优化前 → 后 | CPU 帧提交中位数：优化前 → 后 |
| --- | --- | --- |
| SC-8 待机 | 982 → 24 | 3.2 → 1.2 ms |
| SC-8 步行 | 982 → 24 | 3.1 → 1.2 ms |
| SC-8 尾部动作 | 982 → 24 | 3.2 → 1.1 ms |
| SC-8 完整拆解 | 982 → 24 | 3.0 → 1.2 ms |
| HB-7 振翅 | 172 → 26 | 1.3 → 1.0 ms |

SC-8 的绘制调用减少约 97.6%。步行样本的 GPU 渲染平均耗时从 14.5 ms 降至 8.9 ms，仪表刷新中位数从 1.1 ms 降至 0.1 ms。

CPU 帧提交计时覆盖姿态求解和场景帧更新，GPU 计时通过 `EXT_disjoint_timer_query_webgl2` 获取。仪表更新单独计时。以上是本机样本，不代表所有设备的固定帧率；浏览器刷新率、GPU、驱动和负载都会影响结果。

原始测量摘要及图像误差见 [performance-comparison.json](performance-comparison.json)。

## 实现

- **不透明零件批量绘制**：使用 Three.js `BatchedMesh` 将相同原始材质的几何放在一次批量提交中。按原始精度复制顶点和索引，每个零件仍有独立变换，不做减面、量化或贴图替代。
- **保留原始机械结构**：原始场景图继续驱动关节、液压连杆、拆解和射线拾取。批量渲染副本每帧同步变换，复制矩阵未变化时不重复上传。
- **保留透明与线框行为**：透明材质沿用原来绘制方式。部件隔离和线框模式使用原始网格，保留透明排序、轮廓及阴影效果；这两个模式的绘制调用数没有减少。
- **减少静态计算**：固定几何仅初始化一次局部矩阵；关节、拆解节点与移动外壳继续逐帧更新。复用标注向量、旋转轴与拆解方向，减少临时对象和布局读取。
- **精确计算波形所需的信号**：仪表不再为每个采样点完整求解八条 IK 链与全部尾钳机构。轻量信号函数和完整姿态共享同一套身体、足端与振翅公式，数值测试要求结果严格相等。
- **兼容与预热**：不支持 `WEBGL_multi_draw` 的浏览器自动使用原始网格路径。Loading 内预编译两种绘制路径，模型加载与双击运行方式保持兼容。

批量路径保留原始几何用于拾取和兼容模式，并创建额外的绘制缓冲区，因此会增加部分几何内存占用；模型下载体积没有变化。

## 视觉与交互验证

8 组对照覆盖待机、步行、尾部动作、完整拆解、半拆解加部件隔离、线框、振翅和腹部展开。每组核对网格数、原始顶点数、实际绘制三角形数、像素比、阴影大小、色调映射与曝光。

所有图像检查均通过。最大平均通道差异约为 **0.0017 / 255**；逐通道差异超过 8 的像素占比低于 **0.005%**。检查为浮点变换和边缘光栅化保留微小容差，不宣称每个像素完全相同。

浏览器回归同时检查直接点击拾取、隔离后恢复整机、线框往返、模型切换、动作、拆解、时间轴、快捷键、移动端，以及无 multi-draw 扩展的兼容路径。运动学测试覆盖关节杆长、足端接地和轻量波形的数值一致性。

## 复现

先在独立终端运行 `npm run dev`，保持 5173 端口可用。串行执行两次采样，避免并行渲染影响计时：

```powershell
npm run profile:render -- review/performance/reference-78f4f61 --reference=78f4f61
npm run profile:render -- review/performance/optimized
npm run compare:render
```

对照代码从 Git 只读提取到忽略目录 `review/performance/reference`。两次测试使用相同模型资产。截图与逐场景指标写入对应目录，不影响生产页面；测试用的场景访问和计时包装仅由浏览器测试注入。
